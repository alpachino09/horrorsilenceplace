# Технические решения Sprint 00–01

1. Работа выполняется в существующем checkout `/workspace/horrorsilenceplace`; дополнительные
   worktree не создавались. Исходный репозиторий был пуст, Editor и Unity-проекта в облаке нет.
   Пользователь прямо поручил создавать исходники; они подготовлены как пакет импорта в Unity.
2. Не выбираем вымышленную точную версию Unity/URP/Input System/NGO. Точная версия Editor и пакетов
   должна быть считана из настоящего проекта. Валидатор запишет её при запуске в Unity.
3. Основной ввод — официальный Input System, отдельный `.inputactions`, собственная копия
   `InputActionAsset` на владельца. Прежний однокомпонентный скрипт из переписки в пакет не включён.
4. `Silence.Core` не ссылается на Unity: инвентарь, числовое затухание шума и правила взаимодействия
   можно компилировать и тестировать отдельно. `Silence.Runtime` — компоненты Unity и Input System.
   `Silence.Editor` — генератор и проверки; тесты имеют отдельные сборки.
5. `IWorldAuthority` отделяет запросы от изменения состояния. `OfflineWorldAuthority` повторно
   проверяет зарегистрированного игрока, первый hit raycast, дальность и доступность цели;
   применяет изменение один раз и ограничивает частоту запросов. Это **локальная реализация**,
   не сетевой сервер и не защита от сетевых атак. NGO-адаптер — следующий спринт.
6. Камера, AudioListener и ввод активируются через привязку локального владельца. Мотор и обзор
   также проверяют локальное владение. Чужой объект не должен принимать локальные команды.
7. Генератор использует только примитивы Unity, URP Lit и собственные одноцветные материалы.
   Не использованы сторонние модели, аудио, текстуры, фильмы или платные ресурсы.
8. Генерируем только Bootstrap/Farm_Prototype. Остальные шесть глав пока не созданы;
   полная кампания и редактор внешности из анкеты остаются в плане, а не выдаются за готовые.
9. Прототипное взаимодействие: подбор в 3 слота, переключение дверей, индикатор радио,
   табличка завершения прогулочного маршрута. Это не квестовая цепочка Sprint 07.
   Физический перенос/бросок, управляемая мышью дверь и шум материалов относятся к следующим этапам.
10. Сюжетные названия THAW-9, слабость существ, финалы, размер расширения рюкзака не утверждены
    заново и не зашиты в код. Случайные атмосферные звуки (ответ 44) и запрет случайных событий,
    меняющих прохождение (81), трактуются раздельно; сейчас случайных событий вообще нет.
11. Настройки прототипа: язык RU/EN, чувствительность мыши, VSync и дальность теней.
    Нет постоянного прицела, карты, оружия, крафта, голода или жажды. Качество/40–60 FPS на M1 Pro
    не обещаются без профилирования на устройстве. Пайплайн URP и ProjectSettings владельца
    генератор не перезаписывает.
12. Нет SDK/аккаунтов голосового сервиса и сетевого теста: Host/Client, голос и микрофон не объявлены
    работающими. Для текущего локального прототипа внешние аккаунты игровых сервисов не нужны.

## Дополнения Sprint 02

13. Точная версия Editor теперь подтверждена владельцем: 6000.6.7f1. Для нового адаптера выбраны
    NGO 2.7.0 / Transport 2.6.0 по официальному исходному коду; они не выдаются за уже установленные.
    Проверка Unity API и ILPP всё ещё ожидается. Ошибки Unity6.6 из прежнего этапа учитываются.
14. Сеть вынесена в локальный UPM-пакет: старый режим может компилироваться без NGO, пока пакет
    не добавлен через menu 03. Манифест/версии URP проекта владельца не заменяются.
15. Один мотор служит offline и серверу. CanSimulate отделён от IsLocalOwner: сервер может
    двигать чужого игрока, клиент — только отправлять ввод. Клиентские позиции и deltaTime не принимаются.
16. Первое соединение — локальный/LAN IPv4 без аккаунтов. Во время раунда вход закрыт; восстановление
    посреди игры не изображается готовым. Полное восстановление на checkpoint потребует отдельного этапа.
17. Сетевой генератор копирует сохранённую ферму, затем меняет только копию. Обновление исходников
    сохраняет .meta, Generated и пользовательские сцены; резервирует заменяемый код в Library.
18. Приёмка сети выполняется реальными процессами. Development-only автоматизация не включается
    в Release. PASS требует текущего runId и данных о движении, репликации, инвентаре и disconnect.
    Cloud syntax/unit PASS не заменяет эту приёмку. Визуальная замена временных ассетов — позже по roadmap.

19. После CS0619 в RigidbodyContactEventManager на Unity 6000.6 зависимость NGO 2.7.0 заменена
    на 2.13.3 (локальный модуль 0.2.1). Проверка версии не отключается. EntityId-исправление и
    используемые API сверены с upstream ddd715da4695a278a143d9af3530fd60a3814b73.
    Старый совет downgrade отменён. Повторный запуск Unity и реальный сетевой тест ещё ожидаются.

20. Полученный полный отчёт владельца подтверждает 233 PASS и один FAIL только из-за Transport 6.6.0
    вместо строго 2.6.0. Точный pin валидатора заменён списком двух известных версий 2.6.0/6.6.0.
    Зависимость package.json остаётся минимальной 2.6.0; установленный пакет 6.6.0 не понижается.
    В Console сначала выводятся итог/названия ошибок. Реальная сеть по-прежнему требует запуска.

21. Модуль 0.2.3: при регистрации InteractionGate серверная роль берётся у уже spawned персонажа,
    поскольку NGO создаёт host player раньше in-scene мира. Порядок подтверждён upstream 2.13.3.
    Owner/sender/LOS/range/cooldown проверки сохранены. Новый Host runtime-тест ещё ожидается.

22. После повторного отказа двери добавлена диагностическая трасса 0.2.4 вместо следующей догадки
    об исправлении: физическая клавиша/действие/цель/spawn/RPC/server rejection/Apply/timeScale.
    Подсказка E подтверждена владельцем. Меню 08 копирует сохраняемый между Play и Stop отчёт.
    В Release вызовы и инициализация записи исключены; игровые проверки не ослабляются.


## Игровой блок 0.3.0

23. Прямое последнее поручение владельца разрешает по нескольким направлениям (без дополнительных
    согласований) продолжать полноценные системы за пределами Sprint02. Ожидание приёмки прежнего
    roadmap не блокирует написание кода, но проверка Unity и кооператива не объявляется выполненной.
24. Для первого сквозного цикла семь локаций размещены в одной постоянной сетевой сцене,
    с отдельными NavMeshData и серверным переносом между главами. Это упрощает сохранение
    сетевых ID и authority; все локации пока в памяти. Отдельная загрузка/выгрузка сцен отложена.
25. Все новые материалы/текстуры/геометрия/временные звуки генерируются локально, без покупок,
    сторонних моделей и записей. Новые сюжетные тексты/названия развязок остаются предложением.
26. Инвентарь расширен до пяти элементов, wire protocol изменён на SILENCE-GAME-3.
    Старые исполняемые сборки нельзя смешивать с новыми; обе стороны пересобираются.
27. Микрофон только по явному включению и разрешению ОС, без передачи/сохранения голоса.
    Измерение громкости для ИИ не объявляется proximity voice. Отдельного голосового провайдера пока нет.
28. Автоматическая нативная проверка 12 отключает checkpoint-запись на время теста; частично
    вызывает доменные действия напрямую. Она проверяет игровой runtime, а не реальную передачу
    команд между двумя процессами и не качество навигации по всему уровню.


## Visual Rebuild 2.0

29. Рабочая ветка codex/visual-rebuild. Прямое новое поручение разрешает обратимые визуальные изменения
    без дополнительного подтверждения. Рабочая кампания копируется; текущие GUID и исходники её механик сохраняются.
30. URP 17.6 остаётся: без ProjectSettings/renderer assets владельца миграция на HDRP непроверяема,
    а Mac/M1 Pro остаётся целевой платформой. Общий URP asset не перезаписывается; runtime использует клон.
31. Авторские Blender FBX/PBR и Terrain данные реально включены в репозиторий. Чужие игровые модели,
    фотографии и платные ассеты не включены. Poly Haven endpoints оказались недоступны (HTTP 403).
32. Геометрия развивается только в пределах первого двора. Рельеф вне исходных маршрутов, плоские
    основания и сохранённые интерактивные коллайдеры уменьшают риск регрессии; NavMesh фермы пересобирается.
33. Рендеры в Blender отделены от Native/Metal/FPS evidence. Визуальный результат не объявляется
    фотореалистичным/принятым. До реальных кадров Unity расширение визуальной карты остановлено.
34. Старый updater пропускал FBX/PNG/shaders. Новый копирует выделенные Art/Graphics каталоги,
    резервирует файлы и сохраняет существующие .meta/Generated. Требуется сначала заменить сам updater.

35. Владелец отказался от покупки/извлечения модели Fab в пользу собственной модели через Blender Python.
    Добавлен отдельный генератор custom loft/voxel/rig/IK/19 NLA takes/3 LOD/4K PNG/FBX/.blend.
    Он создаёт новую сцену, сохраняет прежние сцены и при повторном GUI-запуске выбирает новую папку.
36. Автоматический voxel/decimate не выдаётся за production-ретопологию и AAA/фотореализм.
    Существующие gameplay/runtime исходники сохранены. Native Unity prefab/demo подготовлены
    кодом, но не создавались и не проверялись в облаке; высокое существо требует проверки проходимости.

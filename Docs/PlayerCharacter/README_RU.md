# Главный персонаж — подготовка подключения

Референс владельца: **Crossbow Girl**,
https://www.fab.com/listings/edf670ba-1967-4b84-bbea-544847c9b6e2.
Задача касается игрока. Системы монстра здесь не изменяются.

Страница Fab из облака недоступна: прокси возвращает 403. Название и характеристики
предоставлены владельцем; изображения, геометрия и текстуры персонажа не получены.
Внешность, возраст, одежда и лицо не придуманы. Модель, скульптура, текстуры, новые
анимационные клипы и Unity-prefab главного персонажа пока **не созданы**.
Точное сходство и художественный уровень не проверены.

Чтобы начать достоверную реконструкцию внешности, нужны изображения спереди,
сбоку и сзади, а также крупный план лица. Если есть разрешённый к использованию
оригинальный архив модели, можно проверить его вместо восстановления по картинкам.
Бюджет остаётся нулевым; платные ресурсы не приобретались.

## Что уже написано

- `PlayerMotionModel`: сглаживание скорости от фактического перемещения,
  направления вперёд/назад/вбок, вертикальной скорости и события приземления.
  Обрабатываются телепорты, пауза, NaN и бесконечности. Класс не двигает игрока.
- `PlayerAvatarState` и `PlayerAvatarNetwork`: отдельный серверный снимок
  состояния опоры, приседа и переноски предмета/товарища. Добавляется только
  в новую копию player prefab; прежние сетевые пакеты не изменены.
- `PlayerAvatarPresentation`: запись параметров Animator по перемещению,
  подтверждённым состояниям и существующим здоровью/направлению камеры.
  Root motion отключён. Наличие параметров проверяется перед использованием.
- `PlayerAvatarVisibility`: голова/глаза/волосы скрываются отдельно для своей
  камеры и камеры наблюдателя, следующей за этим игроком. Для других камер
  используются исходные настройки. Режим ShadowsOnly сохраняет участие в тенях.
  Проверка этих render callbacks в URP ещё предстоит.
- `PlayerAvatarDefinition`: ссылки на art-prefab, реальный AnimatorController,
  трансформацию и отдельные Renderer головы.
- `21 Player Avatar Workshop`: проверка входных ресурсов, установка в отдельную
  копию **открытой** сцены и её player prefab, проверка ссылок и сборка обеих сторон.

В старом `SpectatorView` добавлены только свойства текущей камеры и наблюдаемого
игрока, чтобы графический компонент мог определить, чью голову скрывать.

## Как будет выполняться установка после создания модели

Сейчас устанавливать нечего: инструмент намеренно отклоняет отсутствующую модель
и контроллер без реальных клипов. Порядок для готового результата:

1. Импортировать подготовленную модель и материалы в Unity, настроить Avatar.
2. Создать `Assets → Create → SILENCE → Player Avatar Definition`, заполнить ссылки
   на модель и контроллер. Указать Renderer головы/глаз/волос относительно корня
   модели. Для рук/туловища нужен отдельный Renderer.
3. Открыть последнюю доработанную игровую сцену с нужным окружением. Исходная
   Campaign может быть старой версией; инструмент использует именно открытую сцену.
4. `SILENCE → 21 Player Avatar Workshop` → проверить настройки → создать копию.
   Результат: `Assets/_Silence/Generated/PlayerAvatar/<дата>/<сцена>_Player.unity`,
   новый `Player.prefab`, постоянный `NetworkPrefabs.asset`, `installation.json`.
5. Проверить текущую сцену, затем выполнить Play и нативные проверки.
6. Из того же окна собрать Host и Client. Новый протокол будет не меньше 5
   и выше протокола исходной сцены. Обе сборки должны содержать новый prefab.

Постоянный `NetworkPrefabsList` создаётся отдельным asset. Исходные списки и сцена
не редактируются; остальные регистрации prefab сохраняются. Публичные API списка
проверены по исходникам официального NGO 2.13.3; запуск в Unity этим не заменяется.

## Что проверено

Отчёты находятся в `Docs/Validation/PlayerCharacter`.
Тесты чистого ядра и проверка синтаксиса не подтверждают Unity API binding,
NGO ILPP, правильность импорта модели, рендеринга или фактический кооператив.
Unity Editor отсутствует в облаке. Нативные проверки перечислены в
`NATIVE_CHECKS_RU.md`; ни одна из них пока не объявлена пройденной.

Характеристики референса с указанием источника: `reference.json`.
Оригинальное задание владельца: `TASK_RU.txt`.

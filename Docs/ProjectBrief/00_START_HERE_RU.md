# SILENCE (рабочее название) — инструкция для Codex

## Задача
Создать **реальный компилируемый Unity 6 URP проект** сюжетного кооперативного хоррора на 1–4 игроков (Windows и macOS). Источник требований: `ORIGINAL_ANSWERS_RU.txt`. Прочитать `01_GDD_RU.md`, `02_ARCHITECTURE_RU.md`, `03_IMPLEMENTATION_ROADMAP_RU.md`, `04_ACCEPTANCE_AND_DECISIONS_RU.md`. При разногласиях: прямые ответы владельца > явно обозначенные проектные интерпретации > технические предложения. Не заменять договорённости молча.

## ПЕРВЫЙ ЗАПРОС ДЛЯ CODEX — ВЫПОЛНИ СЕЙЧАС
Ты senior Unity 6 / C# / multiplayer engineer. Работаешь в корне существующего Unity-проекта (если нет — сообщи, что необходимо создать проект `Universal 3D` в Unity Hub; не выдавай несуществующий Unity проект за созданный). Сначала исследуй дерево проекта, `ProjectVersion.txt`, manifest.json, состояние Git и пакеты. Не удаляй пользовательские файлы.

Работай по `03_IMPLEMENTATION_ROADMAP_RU.md`. В ЭТОМ запуске выполни только Sprint 00 и Sprint 01:
1. Проверь что проект Unity 6 и URP. Зафиксируй точную версию Unity, не меняй её без причины.
2. Организуй каталог `Assets/_Silence/{Scripts,Scenes,Prefabs,Materials,Audio,Art,UI,Settings,Editor,Tests}` с подкаталогами из архитектуры. Добавь базовые `.asmdef` при необходимости; следи за ссылками сборок.
3. Создай `Docs/IMPLEMENTATION_STATUS.md` (фактическое состояние, что готово, что не готово, команды проверки), `Docs/DECISIONS.md`, `Docs/THIRD_PARTY_LICENSES.md` и `.gitignore` под Unity; никогда не коммить `Library/`, `Temp/`, `Obj/`, `Builds/`, приватные ключи.
4. Проверь установленные версии пакетов. Планируй Input System, URP, Netcode for GameObjects, Unity Transport, Multiplayer Play Mode и при необходимости Multiplayer Services — **используй только версии, совместимые с фактическим Unity Editor; не выдумывай номер версии API**.
5. Реализуй первый MVP с **автоматически создаваемой через Editor-меню сценой** `Bootstrap` и `Farm_Prototype`: пол, простой дом/стены, фонарь/точечный свет, персонаж-капсула с камерой первого лица и управлением WASD, мышь, бег Shift, приседание Ctrl, взаимодействие E; с отдельной схемой Input Actions. При отсутствии разрешённых ассетов используйте простые primitives и объясняйте, что это заглушки.
6. Код структурируй по системам с интерфейсами звука и взаимодействия, заложи сетевую архитектуру, но не заявляй готовый мультиплеер без подтверждённого теста двух процессов. Если NETCODE пакеты доступны, добавь безопасный Host/Client/Offline bootstrap с проверкой владельца объекта; иначе отдели зависимости и оставь конкретный TODO.
7. Добавь минимум EditMode-тесты для чистых C# компонентов (noise attenuation math, inventory capacity) и PlayMode-smoke план. Не объявляй тесты пройденными, пока они не выполнены.
8. Убедись, что код не содержит ссылок на отсутствующие ассеты или несовместимые библиотеки. Проверь компиляцию доступным способом; если Unity Editor невозможно запустить из окружения Codex — честно укажи, как пользователь проверит в Unity, и не утверждай, что запускался.
9. Сделай небольшой коммит только если Git репозиторий уже доступен и изменения проверены; не пушь в GitHub без разрешения.
10. В отчёте: конкретные созданные/изменённые файлы, известные ограничения, способ открыть сцену, способ проверить управление и **следующий небольшой шаг**.

Не пытайся реализовать все семь глав за один запуск. Не делай псевдокод вместо нужных .cs/.unity/.asset файлов. Не заменяй работающую систему заглушкой без объяснения. Не создавай фиктивные сетевые/микрофонные функции.

## Целевая игровая фантазия
Тишина — ресурс, малейшее неловкое действие привлекает слепого быстрого хищника. Напряжение должно возникать из симулируемого звука и кооперативных решений, а не из постоянных скримеров. 90% страх, 10% непреднамеренный юмор. 7 полуоткрытых, сюжетно последовательных глав, 4–6 часов суммарно, вариативные финалы.

## Исправление совместимости Unity 6000.6

На машине владельца NGO 2.7.0 вызвал CS0619 в RigidbodyContactEventManager: int-словари
получали EntityId. Рекомендация downgrade отменена. Локальный модуль 0.2.1 требует NGO 2.13.3.
Проверено по официальным исходникам commit ddd715da4695a278a143d9af3530fd60a3814b73:
в новых Unity используются Dictionary<EntityId,...> и поля EntityId; 22 прежние сигнатуры нашего
адаптера присутствуют. Дополнительные четыре проверки покрывают исправление EntityId.
Официальная зависимость Transport осталась 2.6.0. Источники получены по raw GitHub из указанного
upstream commit и сверены с UPM-зеркалом 2.13.3. Это не Unity-компиляция.
Восстановление: вернуть 2.13.3 в Package Manager → обновить исходники через menu 00 из свежего ZIP
→ повторить 06; существующие сцены сохраняются. Последующий Editor-отчёт приведён ниже; фактическая сеть ещё не проверена.

## Регрессия взаимодействия хоста: модуль 0.2.3

После Failures: 0 (скриншот владельца, UTC 2026-10-23T01:49:47.5362360Z) владелец подтвердил
запуск и управление в Host, но сообщил, что двери перестали открываться. Это не тест двух процессов.
По официальному NGO 2.13.3 установлено: HostServerInitialize сначала создаёт персонажа хоста через
HandleConnectionApproval, а затем запускает ServerSpawnSceneObjectsOnStartSweep для объектов сцены.
NetworkWorldAuthority.Register проверял собственный IsServer ещё до спавна мира и мог не создать
InteractionGate для хоста. Все последующие запросы этого участника отклонялись отсутствующим gate.
Теперь проверяется player.IsServer — роль персонажа уже инициализирована перед его OnNetworkSpawn.
Проверки ownership/sender/range/raycast/cooldown сохраняются. Сцена и префаб не требуют регенерации.
Доказательство анализа: Validation/host-interaction-startup-review.json. Синтаксис и структура
перепроверены в облаке. Исправленное взаимодействие в Unity ещё не запускалось.
Регрессия: новый Host → начать раунд → открыть/закрыть дверь E → взять предмет один раз → проверить Tab.
Существующий development smoke --players 1 также проверяет подбор хостом и выявляет отсутствие gate;
он подготовлен, но в облаке не запускался из-за отсутствия Unity-сборки.

## Диагностика неработающей двери: модуль 0.2.4

Владелец повторно сообщил, что дверь не открывается, и уточнил: подсказка «E: Открыть» появляется.
Предыдущая правка не дала подтверждённого исправления. Локальный поиск цели выполняется,
но этап отказа (ввод, spawn цели, RPC, серверная проверка, применение или время анимации) пока неизвестен.
Добавлена трассировка без ослабления проверок: физическая E/действие Input System, сканер, регистрация
actor/gate, запрос/spawn цели, RPC send/receive, причины серверного отказа, результат Apply и timeScale.
Логи имеют метку 0.2.4, чтобы подтвердить загрузку свежего кода. Они пишутся только в Editor/Development.
При новом Play файл Library/Silence/InteractionTrace.txt сбрасывается, после Stop сохраняется.
Меню 08 Copy Interaction Diagnostics копирует файл в буфер. В Development-player используется persistentDataPath.
В Release вызовы диагностики исключены Conditional, инициализация файла не компилируется.
Синтаксис проверен для пяти наборов define; Unity-запуск новой диагностики и исправление двери ещё ожидаются.

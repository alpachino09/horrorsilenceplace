# Sprint 02: установка и проверка

Код подготовлен для настоящего NGO, но **факт соединения ещё не подтверждён**.
В облаке нет Unity Editor и лицензии для сборки. Проверка на твоём Mac — следующий обязательный шаг.
Визуальные объекты остаются временными; художественная замена предусмотрена дорожной картой.

## Если после установки 2.7.0 появилась ошибка EntityId / CS0619

В Unity 6000.6 пакет NGO 2.7.0 использует запрещённое преобразование EntityId → int.
Эта рекомендация отменена. В NGO 2.13.3 соответствующий код использует EntityId без преобразования.
Наш модуль обновлён под NGO 2.13.3; проверка версии сохранена.

1. Открой Window → Package Manager → + → Install package by name.
   Name: `com.unity.netcode.gameobjects`, Version: `2.13.3`. Дождись компиляции.
2. Скачай свежий ZIP этой ветки GitHub и распакуй в новую папку Downloads.
3. Выполни SILENCE → 00 Update Sources From Folder и выбери свежую распакованную папку.
4. Дождись компиляции, нажми Clear в Console, затем SILENCE → 06 Validate Network Farm.
   Уже созданную сетевую сцену повторно создавать/удалять не нужно.

Изменение Library/PackageCache не требуется; исправление берётся из официального пакета.
Полный запуск новой комбинации в Unity всё ещё требует проверки на Mac владельца.

## Простое обновление

Следуй шести шагам [README](../README.md). Скрипт копирует обычные исходники,
не содержит Base64, не заменяет сцены/метаданные/ProjectSettings. Старый код сохраняется в
`Library/Silence/SourceBackups/<дата>`. Установщик UPM подключает локальный пакет и официальные зависимости.
Если Unity не может скачать зависимости, нужен доступ к Unity Registry на машине с Editor;
скопировать отдельные файлы NGO вместо установки пакета недостаточно.

Уже установленные Unity/URP/Input System не заменяются. Требуемые сетевые версии:
NGO **2.13.3**. Transport **2.6.0** — минимальная зависимость пакета; валидатор допускает
2.6.0 и установленный у владельца **6.6.0**. Версию 6.6.0 не требуется понижать.
Это допуск к сетевым испытаниям, а не доказательство работы соединения.
Это выбранные зависимости адаптера, а не утверждение о пакетах, уже установленных у владельца.

## Ручная приёмка

1. Останови Play. Обнови исходники и установи пакет через меню 03. В Console не должно быть красных ошибок.
2. Сохрани одиночную ферму. Выполни 04, затем 06. Отчёт: `Library/Silence/NetworkValidation.txt`.
   В конце ожидается `Failures: 0`. Валидатор проверяет сцены/ссылки; это ещё не сетевой тест.
3. Открой `Assets/_Silence/Generated/Sprint02/Farm_Network.unity`. В Play выбери «Создать сессию»,
   дождись игрока, нажми «Начать раунд», затем «Продолжить». Проверь WASD, мышь, Shift, Ctrl, Space, F, E, Tab, Esc.
4. Останови Play. Нажми **05 Build Host and Client**, выбери отдельный каталог для сборок.
   Активный Build Profile: Mac (на Mac), Windows64 или Linux64 с установленным модулем сборки.
   Сборщик задаёт только сетевую сцену, не меняя список сцен других пользовательских сборок.
5. Нажми **07 Launch Host and Client**, выбери каталог с папками Host и Client.
   На Mac команда запускает отдельные процессы даже при одинаковом bundle identifier.
   Host: «Создать сессию». Client: адрес `127.0.0.1`, порт `7777`, «Подключиться».
   На Host должно быть 2/4. Начни раунд. Каждый двигает только своего игрока и видит другого.
6. Подойди двумя игроками к одному предмету и нажми E почти одновременно. Предмет должен исчезнуть у обоих,
   оказавшись только в одном инвентаре. Проверь дверь и индикатор радио с обеих сторон.
7. Возьми три предмета; четвёртый не должен исчезнуть при полном инвентаре.
   После общего подбора предметов на всех может не хватить: для этого случая запусти новый раунд.
8. Проверь стену/закрытую дверь, дальность, приседание под навесом, фонарь другого игрока и прыжок.
9. Закрой Client. На Host капсула клиента должна исчезнуть без красных ошибок. Вход во время раунда
   должен быть отклонён. Выйди в чистое лобби; создай сессию и подключи Client заново.
10. Отключи Host: Client должен получить сообщение и вернуться в лобби. Повтори генерацию 04:
    существующие сцены не должны измениться. Проверь прежний Sprint01 через Bootstrap.
11. Повтори с четырьмя процессами по ресурсам компьютера. Пятый игрок в заполненном лобби должен получить отказ.
    Для LAN включи на Host флажок локальной сети, на Client укажи IPv4-адрес Mac-хоста.

Меню использует мышь; полная навигация меню геймпадом пока не готова. Постоянного прицела нет.
Editor плюс отдельный Client полезны для отладки, но приёмка требует **двух исполняемых сборок**.

## Автоматическая проверка настоящих процессов

Нужен Python 3 и готовые **Development**-сборки из меню 05. Из распакованного репозитория:

```bash
python3 Tools/run_network_smoke.py --host-build "/путь/Builds/Host/SILENCE.app" --client-build "/путь/Builds/Client/SILENCE.app" --players 2
```

Повтори с `--players 1`, затем `--players 4`. На Windows запускай `python` и передавай пути к `.exe`.
Поддерживается исполняемый файл Linux. Runner выбирает локальный UDP-порт и отдельный runId.
Сборки работают без окна: ввод подаёт только development-тест, не ввод ОС.

Сценарий: подключение нужного числа процессов → старт хоста → движение каждым игроком →
серверный перенос в отдельную тестовую зону → общий подбор одного предмета →
проверка инвентарей/репликации → выход клиентов → проверка удаления игроков и освобождения мест на сервере.
Тестовый перенос и автоматический ввод компилируются только для Editor/Development; в Release их нет.
Зона теста находится за пределами фермы; обычное прохождение её не использует.

Доказательства: новый `TestResults/Network-<runId>/`, отдельные JSON/логи процессов и summary.json.
**PASS** означает выполнение проверок сценария, а не всю ручную приёмку выше.
Отсутствие файлов, старый runId, timeout, NaN, недостающие игроки и ненулевой exit code дают FAIL.
Если сборки нет, runner завершится ошибкой, ничего не имитируя.

## Если в Host не открывались двери

Модуль 0.2.3 исправляет регистрацию взаимодействий при спавне персонажа раньше мира.
Останови Play, обнови исходники через 00 из свежего ZIP и запусти новый Host/раунд.
Существующая сцена сохраняется. Проверь дверь E, повторное закрытие, затем подбор предмета и Tab.
Это исправление кода; фактический результат владельца после обновления ещё ожидается.
Для сборок обязательно повтори smoke --players 1: он проверяет, что именно хост способен взять предмет.

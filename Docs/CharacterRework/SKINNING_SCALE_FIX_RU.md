# Body_Clothed / Basic_Idle / 130 м — обновление 0.4.7

Пользовательский Unity 6000.6.7f1 после 0.4.6 измерил отдельную позу в
`Basic_Idle`, t=0, как `(47.58, 130.00, 39.87)` м. Значения подозрительны на
сотенный масштаб, но полного предыдущего JSON с масштабами и локальными
размерами нет. Причина в конкретном Avatar на Mac пока не подтверждена.

## Что теперь считает установщик

Редакторский `SkinPoseSampler` получает положение каждой вершины напрямую:

`actorVertex = Σ weight[i] × worldToActor × boneWorld[i] × bindpose[i] × shapedVertex`

Масштаб импортированного FBX уже входит в bind poses и матрицы костей.
Матрица renderer не применяется к этому результату повторно. Отдельные
bounds в метрах получаются по самим actor-вершинам, локальные bounds для
culling — обратным переносом этих же вершин в систему renderer. Не требуется
угадывать систему масштаба результата `BakeMesh(false)` и делить на 100.

Это редакторский расчёт при установке; в игровом кадре CPU skinning не
добавлен. Mesh vertices, bind poses, Avatar, FBX import settings, исходные
клипы, анимационные масштабы костей и геометрия не переписываются.
Остаются четыре проверенных влияния на вершину, как и при SkinQuality.Bone4.
Учитываются активные blend shapes до skinning, в том числе несколько
кадров, интерполяция и экстраполяция. Настоящие NaN и гигантские позы
по-прежнему прерывают установку с сохранением исходного мира.

Добавлено измерение оболочки торса по `Basic_Idle`; прежний фильтр имени
учитывал только `Idle` и `|Idle` и мог оставить запасные размеры.

## Если проблема в самом ретаргетинге

Прямой расчёт тоже покажет гигантскую позу, если на самом деле увеличены
кости или несовместимы bind poses. Такой случай нельзя чинить уменьшением
чисел bounds. В Console появится отдельная обычная запись
`SILENCE CharacterRework diagnostics` с полным JSON. Можно скопировать её
целиком; искать файл вручную больше не обязательно.

Тот же JSON остаётся в `Library/Silence/CharacterReworkFailure.json`.
Он содержит размеры skin до и после позы, Avatar path/humanScale,
масштабы и расстояния костей до/после анимации, а при большой позе —
сравнение с прежним BakeMesh. Данные сохраняются после удаления неудавшейся
копии. Эти данные позволят отличить импорт/Avatar от ошибки замера.

## Установка

1. Останови Play и сохрани **текущий улучшенный игровой мир** `..._Motion`.
2. Скачай `Downloads/SILENCE_HumanMotion_0.4.7.zip` через **Download raw file**,
   распакуй. **SILENCE → 00 Update Sources From Folder** → выбери корневую
   папку обновления с Assets и LocalPackages. Дождись компиляции.
3. **SILENCE → 27 Character Rework and Audit → Создать копию мира:
   исправить и проверить персонажей**.
4. При успехе откроется `..._Character`. Нажми проверку, затем Play,
   создание сессии/начало раунда, V для смены вида.

Повторять 25/22, менять Scale Factor, протокол, FBX и старую Campaign не
нужно. Установщик по-прежнему работает с копией текущего мира и игроков.
Для кооператива обе сборки надо получить из одной успешно созданной сцены.

## Проверки и ограничения

- 213 Core-тестов прошли. Новые проверяют компенсацию 100/0,01,
  повороты, перенос, отражение, неравномерный масштаб и четыре веса.
  Настоящее сотенное увеличение скелета остаётся увеличением, а не
  исправляется делением на константу.
- 448 сравнений с реальными деформированными вершинами `Body_Clothed`
  собственной Blender-модели: 64 вершины в семи позах Idle, Walk, Run,
  CrouchIdle, Jump, Death. Ожидаемые позиции получены через Blender depsgraph,
  а проверяемый код — тот же `SkinPoseModel`, который вызывает установщик.
  Это независимая проверка skinning, **не** Unity Humanoid-ретаргетинга.
- Предоставлено 12 новых native-тестовых случаев для Unity Test Runner:
  FBX-иерархии с компенсирующими масштабами, смешанные веса, blend shapes,
  перенос мира, сравнение с native BakeMesh и сохранение защиты от большой
  деформации. Они **не запускались**: Unity Editor в облаке отсутствует.
- Проверка C# source/guards/выбранных scope diagnostics и архив проверены
  отдельно. Полная компиляция Unity API, ILPP, Play, графика и Host/Client
  остаются непроверенными. Нельзя считать сбой на Mac подтверждённо
  устранённым до успешного выполнения 27 там.

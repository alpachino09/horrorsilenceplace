# SILENCE Character V2 — установка 0.6.0

Это техническое обновление нынешнего персонажа, материалов, рук и средств
проверки. Оно не содержит новую купленную модель или готовые записи mocap.
Реальные пересечения в нескольких собственных запасных клипах перечислены
в [отчёте](REPORT_V2_RU.md); их не объявляем устранёнными одним IK.

## Установить код

1. В Unity останови Play, сохрани **свой нынешний игровой мир**, затем закрой Unity.
2. Скачай `Downloads/SILENCE_HumanMotion_0.6.0.zip` на GitHub кнопкой
   **Download raw file**. Распакуй архив в «Загрузки».
3. Открой обычное приложение macOS **Терминал** и вставь:

   ```bash
   bash ~/Downloads/SILENCE_HumanMotion_0.6.0/Install_Update.command
   ```

4. В появившемся окне выбери корень **твоего Unity-проекта**: папку, внутри
   которой одновременно есть `Assets`, `Packages`, `ProjectSettings` и
   `LocalPackages`. Здесь выбирается проект; это отличается от выбора
   распакованного обновления старым пунктом 00.
5. Установщик проверит контрольные суммы и сохранит резервную копию кода.
   Открой проект в Unity и дождись компиляции.

Используй **Install_Update.command**. Старый **Install_Bounds_Fix.command**
исправляет только два файла старой проверки bounds и не устанавливает V2.
Импортированные Kevin Iglesias и ObjectiveEnvironment_Assets, сцены, модели,
текстуры, настройки Unity и существующие `.meta` полный установщик сохраняет.
Папка backup и результат каждой операции печатаются в Терминале.

## Применить к нынешнему миру

1. Открой **последний игровой мир с твоим окружением и героиней**. Не открывай
   старую Campaign ради обновления. Просмотр 23 и площадка проверки не являются
   игровым миром. В игровой сцене должен быть один NetworkManager.
2. Открой **SILENCE → 29 Character Audit and Review**. В заголовке — **0.6.0**.
3. Нажми **«1. Проверить текущих персонажей без изменений»**. Результат:
   `Library/Silence/CharacterProjectAudit.json`; его можно скопировать кнопкой.
4. Один раз нажми **«2. Применить исправления к копии нынешнего мира»**.
   Подождёт проверку реального Humanoid и клипов; откроется созданная копия.
   Материалы и при необходимости mesh/controller копируются вместе с ней.
   Не нажимай эту кнопку многократно: каждый запуск создаёт ещё одну копию.
5. Нажми **«Проверить исправленную копию»**, затем Play → создать сессию →
   начать раунд. Клавиша **V** переключает камеру. Проверь руки сначала без
   предметов, затем ходьбу/бег/присед, **E**, **F/R/H** при установленном фонарике.
6. Для кооператива собери **обе** новые сборки из этой копии; старую сборку
   со старым кодом не используй для оценки новых камер и анимаций.

Согласование IK, сглаживание и камера работают уже после замены кода.
Новая копия нужна для применения сохранённых настроек материалов/аудита к
реальным ассетам. `Failures: 0` подтверждает ссылки и настройки, а не качество
походки, отсутствие всех пересечений или работоспособность четырёх клиентов.

## Отдельная площадка: 15 сценариев

В 29 нажми **«3. Создать отдельную площадку 15 проверок»**, затем Play.
Она использует **player prefab и клипы текущего мира**, не требует отдельно
PolyOne и не заменяет окружение в исходной сцене. Есть полы, ступеньки, склон,
низкий потолок, тестовая дверь и подбор батареек.

Выбери сценарий → **«Записать сценарий»** → выполни действие и осмотри модель
→ **«Закончить запись»**. Только после осмотра поставь «нормально» или «дефект».
Запись сама не получает успешный результат. Панель показывает измерения:
разведение плеча, максимальный сдвиг кисти между кадрами, изменение длин рук,
движение опорной стопы относительно поверхности и неразрешённые ограничения.
Это диагностические величины; они не доказывают отсутствие mesh intersections.

Для исходных анимаций есть **«Просмотреть все исходные клипы»**. В этом режиме
временно выключаются игровые изменения костей, время gameplay остановлено,
а клип проигрывается отдельно. Возврат восстанавливает прежние флаги компонентов,
контроллер, время и захват мыши. Так можно отличить дефект записи от ошибки IK.

Кнопки **15 / 30 / 60 FPS** полезны для поиска рывков. При выходе из площадки
лимит FPS и VSync восстанавливаются. Это не измеренный профиль производительности
сборки. В площадке заряд фонарика сокращён до 12 секунд только для проверки
разрядки; игровой prefab не меняется.

**«Сохранить отчёт»** записывает `Library/Silence/CharacterReviewLatest.json`.
В сборке используется `Application.persistentDataPath/Silence`. В отчёте
отделены измерения и ручное подтверждение. Без калиброванной модели фонарика
четыре его сценария недоступны; один источник света не подтверждает хват.
Сценарий «камера другого игрока» в offline-площадке тоже недоступен:
его проверяют настоящими Host/Client в игровом мире.

Чтобы вернуть мир: **останови Play → 29 → «Вернуться из площадки в игровой
мир»**. Откроется именно сцена, из которой создана последняя площадка,
а не исходный старый прототип. Также она записана в `review-source.json`
рядом с площадкой. Проверочный отчёт не вставляет площадку в Build Settings.

## Если источник движения плохой

Для `WalkBack`, `CrouchIdle`, `WoundedWalk`, `StrafeLeft`, `StrafeRight` из
собственного Blender-исходника найдены пересечения выбранных кисть/тело
поверхностей. В `Death` они тоже есть, хотя текущий controller может использовать
другой клип смерти. Версия на Mac могла быть изменена; сначала осмотри свой
сырой клип. Процедурные ограничения не считаются заменой качественной записи.

Конкретный путь замены: **29 → «Подобрать реальные замены движений в окне 28»**,
папка **Assets/Kevin Iglesias**, назначить имеющиеся реальные Humanoid-клипы.
Для проблемных ролей есть «Ходьба назад», «Покой в приседе», «Шаг влево/вправо»
и новые необязательные **«Ранение: покой / ходьба»**. Idle, Walk и Run обязательны.
Пустое поле означает, что подходящая запись не найдена однозначно: отсутствие
не выдаётся за импорт. Если подходящего клипа нет в бесплатном пакете, нужен
отдельный лицензированный клип или правка исходной анимации. Окно 28 сохраняет
свои копии, измеряет cadence на этом Avatar и не меняет оригиналы ассета.

Фактическую модель фонарика и её маркеры настраивают в существующем окне 24.
Новые `leftPalmInward/rightPalmInward` в FlashlightProfile — необязательное
направление внутрь ладони в её локальных координатах. Обычно ось сгиба
вычисляется по костям; при неоднозначной геометрии пальцы не гнутся по случайной
оси. Сверь направления, силу хвата, крышку и контакты на **своей** модели.

Полный отчёт по восьми пунктам: [REPORT_V2_RU.md](REPORT_V2_RU.md).

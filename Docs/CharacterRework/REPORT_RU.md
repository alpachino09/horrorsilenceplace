# Результат 0.4.4 и границы проверки

## Что удалось установить

Проверена реальная исходная HoodedGirl из сохранённого Blender 5.2.3:
47 игровых мешей трёх LOD, 20 собственных клипов, 260 выборок поз.
Нет вершин с ненормализованными весами, более четырьмя влияниями,
неизвестными deform bones, потерянным Armature modifier или вырожденных граней.
Переназначать все веса или произвольно менять пропорции без найденной причины
не стали. Это не доказывает правильность ретаргетинга на Mac.

Пробные расстояния до открытой поверхности торса дают подозрительные участки
в ходьбе/беге/поворотах. Знак ближайшей нормали на открытой одежде не является
надёжным тестом попадания внутрь; эти показатели сохранены как диагностика,
а не доказательство устранения всех пересечений. Осмотрены существующие
рендеры самой модели Run и CrouchWalk. Новые Unity-рендеры здесь не создавались.

Исходный material manifest задаёт непрозрачные кожу и одежду; альфа-тест нужен
волосяным карточкам. Созданные на Mac материалы облаку недоступны. Поэтому
их исправление выполняется на реальных копиях в меню 27, а случайная
прозрачность исходных материалов не выдаётся за уже доказанный дефект.

В коде найдены конкретные причины конфликтов:

- после раннего guard фонарик мог перезаписать вес IK левой руки нулём;
- постоянные hint/goal веса могли переживать окончание предыдущего действия;
- локальный Euler-наклон груди предполагал оси импортированной кости;
- кисть при снятии/установке крышки получала поворот на 720°, как сама крышка;
- одна защита от заднего скрещивания кистей не учитывала объём торса,
  сгиб локтя, колени в приседе, голову или досягаемость цели.

## Что реализовано

1. Один координатор явно вызывает этапы: очистка goals → feet/body IK →
   взаимодействие → фонарик → общие ограничения. Остальные OnAnimatorIK
   делегируют ему и не записывают те же цели повторно. Это снимает зависимость
   от порядка отдельных сообщений Unity. Для controller без координатора
   остаётся прежний fallback порядка 675/680/700/750/780. Восстанавливаются
   hint weights; фонарик пропускает первый callback до готовности своей цели,
   смерть не переопределяется живым хватом. Реальный Play ещё требуется.
2. Общий геометрический solver: длины плеча/предплечья измеряются по костям,
   сгиб локтя ограничен 8–150°, есть устойчивый pole, ограничение досягаемости,
   проверка верхней части руки и предплечья, объёмы торса/бёдер/голеней/головы.
   Положение торса учитывает реальный позвоночник и присед. Неподходящая
   скрещённая поза без владельца руки плавно возвращается к расслабленной.
3. Границы торса измеряются на нейтральной одежде по влияниям позвоночника;
   при отсутствии измерения используются обозначенные размеры по умолчанию.
   Это приближённые капсулы, не точная mesh self-collision/cloth simulation.
   Есть ограниченное число итераций и счётчик `UnresolvedContacts` для случаев,
   которые не удалось разрешить. Полного отсутствия пересечений не заявлено.
4. Фонарик запрашивает ту же достижимую позицию правой кисти перед расчётом
   контактов левой. Модель уже привязана к реальной кисти через grip marker.
   Кисть выполняет перехваты в пределах ±40°, крышка имеет отдельное движение.
   Батарейный gameplay/state machine и момент расхода не менялись.
5. Наклон груди переводится из системы координат тела через родителя кости.
   Существующие Blend Trees, gait/idle, повороты, breathing, foot IK, carry,
   wounded, jump/fall/land/death и network animation state сохраняются.
   Новая записанная mocap-анимация не создавалась и не выдумывалась.
6. Для известных твёрдых материалов создаются копии: URP Opaque, alpha 1,
   blending One/Zero, ZWrite, обычная очередь и shadow/depth passes.
   Текстуры, RGB, normal/mask maps сохраняются. Glass/cornea/lens,
   Hair_Cards/lashes сохраняют собственные материалы. Неопознанные материалы
   перечислены для проверки; неизвестный shader твёрдого материала вызывает
   понятный отказ вместо тихой замены. Фокус текущего проекта — URP.
7. Нативный аудит проверяет Humanoid-цепочки, bone references, bindpose count
   и skin weights. Только фактически ненормализованные веса исправляются
   в копии меша. Потерянные/отрицательные/нулевые веса не угадываются.
8. На реальном Avatar в приватной preview-сцене измеряются все существующие
   Humanoid-клипы controller (кроме отдельного additive BreathGame): девять
   временных выборок, BakeMesh, локальные bounds и запас. Недопустимо далёкий
   уход меша от капсулы вызывает отказ с указанием проверить in-place клипы.
   Выборки не являются доказательством всех возможных blended-поз.
9. Меню 27 сохраняет копию открытого мира/каждого человеческого player prefab,
   остальные сетевые объекты и монстр сохраняются. Полная модель видна другим
   игрокам и снаружи, голова скрывается только из глаз. Прозрачность всего тела
   как обход камеры не используется. Протокол новой копии >= 9.

## Проверено доступными средствами

- 198 NUnit/.NET Core-тестов прошли; 13 новых случаев анатомии рук,
  досягаемости, симметрии, коленей и перехватов кисти.
- Стресс-проверка 1000 целей подтверждает сохранение обеих длин костей
  и конечность результата. Это тест геометрической модели, не Unity Animator.
- Реальная Blender-проверка 47 мешей и 260 поз; отчёт:
  `Docs/Validation/CharacterRework044/source-audit.json`.
- C# syntax/guards/выбранные scope-ошибки и структурные проверки записаны
  рядом в `source-checks.txt` и `structure.json`. Это не Unity API compilation.
- Новые API сверены с UnityCsReference 6000.6.7f1; фактические исходники
  URP и Animation Rigging исследованы и перечислены в references.json.
- ZIP проверяется на hashes, полноту исходников, совместимость с updater,
  отсутствие чужих animation assets и перезаписи `.meta`.

Четыре новых CharacterReworkReferenceTests поставляются для Unity, но не
запускались. Вместе с прежними шесть — десять native-тестов для последующей
проверки. Unity Editor, ILPP, визуальный Play, четыре сборки и FPS здесь
недоступны. Ни их успешное выполнение, ни AAA-качество не заявляются.

## Что остаётся до полной визуальной приёмки задания

Нужны проверка именно созданных на Mac поз и материалов, тесты первого/
третьего лица и кооператива. При подтверждённой неверной форме/деформации
mesh или Avatar нужны их фактические данные; текущий аудит исходных весов
таких неисправностей не обнаружил. Детальная художественная переработка лица,
одежды, топологии и всех клипов в этой версии не выполнена.

Не хватает специальных направленных crouch/start/stop/flinch клипов;
прежний CrouchWalk остаётся общим fallback. Нет оснований обещать отсутствие
любого foot sliding при любых blended-переходах до тестов.

Самостоятельный реальный файл чёрного фонарика в облако не поступил. Если он
уже импортирован на Mac, сохраняется его существующий profile. Нельзя честно
подтвердить посадку каждого пальца, контакт ладони с корпусом, резьбу крышки
и батарейки без этой геометрии/маркеров и визуальной калибровки. Это остаётся
конкретной незавершённой частью, а не «готовой ультрареалистичной анимацией».

Полученный текст задания заканчивается внутри раздела третьего лица словом
«Плеч». Дополнительные требования после этого места в файле отсутствуют.

# Сетевой контракт Sprint 02

Реализация: `LocalPackages/com.silence.multiplayer`. Используются API официального NGO 2.13.3,
проверенные по commit `ddd715da4695a278a143d9af3530fd60a3814b73`.
Зависимость Transport 2.6.0 взята из его package.json. Установка через UPM; версии действительно
установленных пакетов проверяет Editor-валидатор. В облачном Unity пакеты не установлены:
Editor отсутствует, Unity Registry в этой среде ответил HTTP 403.

## Команды и полномочия

- NetworkSession обрабатывает approval: резервирует до 4 уникальных мест, проверяет протокол,
  назначает точки появления. Во время раунда вход закрыт; повторный вход возможен в новом лобби.
- NetworkPlayer принимает ввод только владельца. RPC использует InvokePermission.Owner и
  проверяет RpcParams.Receive.SenderClientId; актёр определяется по серверному объекту.
- Пакет ввода не содержит позицию, deltaTime, скорость или клиентский raycast. Сервер нормализует оси,
  проверяет конечность чисел, последовательность и частоту; вызывает общий CharacterController-мотор
  с шагом 1/30 с. Потеря ввода дольше 0.35 с останавливает движение.
- JumpSequence предотвращает повторное выполнение одного прыжка. Доставка ввода надёжная;
  это базовая реализация для LAN, не готовая схема для плохого интернет-соединения.
- Положение/высота/направление/фонарь передаются server-write NetworkVariable. Клиенты сглаживают
  позицию; взгляд локален. Предсказания движения и rollback нет: задержка движения на высоком ping
  остаётся ограничением этого этапа.
- Камера/AudioListener/Input включаются только у своего игрока. Удалённые капсулы видны и имеют разные цвета.

## Предметы и общая сцена

Сканер отправляет NetworkObjectId цели и последовательность запроса. Хост повторно проверяет
участника, cooldown, дальность, первый raycast-hit и CanInteract. Затем вызывается Apply.
Подбор сразу помечает предмет использованным и выключает коллайдер/рендерер. Второй запрос
уже не может добавить его в другой инвентарь. Корень остаётся spawned для репликации.
NetworkInteractable передаёт логическое состояние предмета/двери/индикатора/выхода без вызова Apply на клиентах.
Три слота инвентаря отправляются только владельцу; snapshot проверяется целиком до замены.
Идентификаторы предметов ограничены 61 байтом UTF-8 (FixedString64Bytes).

NoiseSystem получает события взаимодействия только от сервера. Шаги и ИИ относятся к Sprint 03.
Игра рассчитана на доверенный хост: защита клиента от злонамеренного хоста не реализована.

## Жизненный цикл и ограничения

Отключение освобождает slot; NGO удаляет принадлежащего клиенту игрока. Выход/обрыв соединения
останавливает менеджер и загружает чистое сетевое лобби. Повторное подключение в лобби получает
новое место; восстановление инвентаря покинувшего игрока во время раунда отсутствует.
Host migration, Relay, Steam и интернет-приглашения не реализованы.

Sprint01 сохраняется. Генератор Sprint02 копирует сохранённую ферму в новую сцену,
меняет сетевую копию и создаёт новый префаб. Повторная команда сохраняет существующий результат.
Частично созданный каталог не перезаписывается: его надо сохранить/переименовать перед повтором.

## Приёмка

[Инструкция](SPRINT02_RU.md): компиляция в настоящем Unity → валидатор → две сборки → реальные
1/2/4 процесса → одновременный подбор и disconnect → оставшаяся ручная регрессия.
Runner требует текущий runId, движение, приходящие pose ticks, одну камеру/слушателя/ввод,
одного владельца спорного предмета и очистку отключившихся игроков.
Отсутствие доказательств, старый результат, timeout и ненулевой exit code дают FAIL.
Эти сетевые проверки подготовлены, но **ещё не выполнены** в Unity.

# Сетевой контракт и следующий Sprint 02

Цель — 1–4 участника. Сейчас реализован только offline-путь; константа максимального числа
игроков и интерфейс полномочий не являются сетевой реализацией.

## Уже отделено

- PlayerContext: локальное владение, камера, ввод, инвентарь, ссылка на IWorldAuthority.
- FirstPersonMotor.Simulate: явный шаг движения для тестов и будущего адаптера предсказания.
- InteractionScanner: определяет локальную цель, отправляет запрос; не меняет инвентарь/дверь напрямую.
- OfflineWorldAuthority: проверяет актёра, повторный raycast/дальность, частоту и состояние цели,
  затем вызывает внутренний Apply. Локальные запросы исполняются синхронно.
- NoiseSystem: отдельное числовое событие без зависимости от AudioSource и без передачи PCM.

## Необходимый следующий этап

1. Получить фактические `ProjectVersion.txt`, `manifest.json`, `packages-lock.json` и отчёт валидатора.
2. Через Package Manager подобрать совместимые Netcode for GameObjects и Unity Transport;
   Multiplayer Play Mode — дополнительный инструмент, не замена тесту двух процессов.
3. Добавить отдельную сборку сетевого адаптера с реальными API установленных пакетов.
   NetworkObject IDs должны заменить локальные ссылки и offline SourceId (1) при передаче по сети.
4. Сервер выводит личность отправителя из RPC/session metadata и находит собственный PlayerContext.
   Не принимать в качестве авторитетных actor ID, позицию камеры, результат raycast, количество
   предметов, здоровье или таймер, присланные клиентом. Валидировать допустимое положение/направление.
5. Инвентарь, потребление предмета и состояние двери изменять на сервере атомарно. Репликация
   не должна повторно вызывать Apply или создавать второй предмет. Ограничения/идемпотентность
   запросов, disconnect и late join требуют отдельной реализации и тестов.
6. Только владелец включает ввод, камеру и AudioListener; другие игроки отображаются внешней моделью.
   Серверные объекты и данные должны существовать независимо от локального HUD.
7. Подтвердить Host + Client в двух отдельных процессах; затем 1/2/4 игрока по ресурсам.
   Обязательные сценарии: одновременный подбор, закрытая дверь/стена, чужой actor, disconnect,
   повторный вход, отсутствие дублирования и корректное число камер/аудиослушателей.

До этих проверок сетевые кнопки Host/Client и «подключение» не имитируются.
Relay, аккаунты внешних сервисов, Steam и голос не блокируют первый LAN-тест и относятся к последующим этапам.
